# VOID CLI Simplification — Roadmap Draft

**Status:** Draft  
**Motivation:** Current invocation is too long for daily use:
```
mvn process-resources -q && mvn exec:java \
  -Dexec.mainClass=core.resolvers.locator.json.JsonMigratorCli \
  -Dexec.args="--sync tests.demo.pages.DemoLoginPage"
```
Goal: `void sync DemoLoginPage` — or a slash-style discovery menu.

---

## Problem Statement

Three pain points:

1. **Verbose** — full class name + Maven exec boilerplate every time
2. **Not discoverable** — no `--help` or command list; developer must remember exact flags
3. **Classpath friction** — `mvn process-resources` must precede every sync or stale-cache errors occur

---

## Options Considered

| Option | Invocation | Discoverability | Effort |
|--------|-----------|-----------------|--------|
| A — Shell wrapper script | `.\void sync DemoLoginPage` | None (no help) | Trivial |
| B — Maven plugin | `mvn void:sync -Dclass=DemoLoginPage` | `mvn void:help` | Medium |
| C — Standalone Picocli CLI | `void sync DemoLoginPage` | `void --help`, tab completion | Medium-High |
| D — Interactive REPL | `void` → `/sync`, `/print`, `/write` | Menu on launch | High |

---

## Recommended Path

### Phase 1 — Shell wrapper (immediate win, no new code)

Add `void.bat` / `void.sh` to the project root. Wraps the full Maven command with short aliases:

```bat
@echo off
rem void.bat — VOID developer CLI wrapper
set CMD=%1
set CLASS=%2
if "%CMD%"=="/sync"  goto sync
if "%CMD%"=="/print" goto print
if "%CMD%"=="/write" goto write
echo Commands: /sync /print /write /write-conventional
goto :eof

:sync
mvn process-resources -q && mvn exec:java -Dexec.mainClass=core.resolvers.locator.json.JsonMigratorCli -Dexec.args="--sync %CLASS%"
goto :eof
```

Invocation: `.\void /sync tests.demo.pages.DemoLoginPage`

**Win:** Zero code changes. Solves verbosity immediately.  
**Gap:** No class-name shorthand; still needs FQCN. No tab completion.

---

### Phase 2 — Maven plugin goals (proper integration)

Create `void-maven-plugin` with lifecycle-aware goals. Resource processing is implicit — the plugin runs after `process-resources` by default.

```xml
<plugin>
  <groupId>io.github.aryan-vashishth</groupId>
  <artifactId>void-maven-plugin</artifactId>
  <version>0.2.0</version>
</plugin>
```

Goals:
- `mvn void:sync -Dclass=DemoLoginPage` — resolves short name to FQCN via classpath scan
- `mvn void:print -Dclass=DemoLoginPage`
- `mvn void:write -Dclass=DemoLoginPage`
- `mvn void:help` — lists all goals

**Win:** Classpath timing solved by plugin lifecycle binding. Short class names via scan.  
**Gap:** Still `mvn` prefix. Maven overhead (~3–5 s JVM startup).

---

### Phase 3 — Standalone Picocli CLI (best DX)

Package the CLI as a fat JAR using Picocli. Installable as a native tool.

```
void --help

Commands:
  sync    Generate/update .properties template and write locators.json
  print   Print JSON for a page class to stdout
  write   Write JSON to the default output directory

Usage:
  void sync <ClassName>          e.g. void sync DemoLoginPage
  void sync <fully.qualified>    e.g. void sync tests.demo.pages.DemoLoginPage
```

Features:
- Short name resolution — `DemoLoginPage` resolved by scanning `tests.*` packages
- Tab completion generated by Picocli
- `--prune` flag passthrough
- Colors and structured error messages

**Win:** Full discoverability. Fast. Works outside Maven.  
**Gap:** Requires JAR on PATH or installation step. Classpath must still include project classes.

---

### Phase 4 — Class name auto-resolution (cross-phase enhancement)

Available to Phase 2 and Phase 3. Allows `DemoLoginPage` instead of `tests.demo.pages.DemoLoginPage`:

1. Scan `tests.**`, `elements.**` for classes whose `getSimpleName()` matches
2. If unique match → use it
3. If ambiguous → print candidates and exit
