# I4.5 Pre-Implementation Audit

**Phase:** runtime-redesign I4.5 -- Driver subsystem re-homed as platform internals
**Date:** 2026-07-29
**Verdict:** READY -- deliverable is the ArchUnit rule; one quick cleanup; eight named exceptions

---

## Scope Reminder

Declare and enforce `core.driver` as Selenium-executor internals: only
`core.engine.selenium.*` may import from `core.driver.*`. Physical package
move is optional and decided at activation -- NOT in scope for this phase.
Import cleanup in `core.utils` (Waiter/driver references) and `core.runtime`
(post-4.2 residue) per the plan; broader `core.utils` dismantling stays in 9.2.

---

## Findings

### D1 -- `EnumResolver.printEnumFormat` uses `Waiter.get()` (fixable in-phase)

**File:** `src/main/java/core/utils/EnumResolver.java:23`

`printEnumFormat(By)` calls `Waiter.get().until(...)` to obtain a `WebDriverWait`.
`Waiter` is the only `core.driver` type imported by this class. No callers of
`printEnumFormat` exist elsewhere in the repo. Fix: change signature to
`printEnumFormat(By locator, WebDriver driver)`, replace `Waiter.get()` with an
inline `new WebDriverWait(driver, Duration.ofSeconds(10))`. Removes the `core.driver`
import entirely.

**Severity:** LOW. No callers; mechanical change.

---

### D2 -- `Via.webElement(UIElement)` and `Via.webElement(By)` use `DriverContext.getActiveDriver()`

**File:** `src/main/java/core/interactions/Via.java:289,295`

Two convenience overloads that omit the `WebDriver` parameter reach into
`DriverContext.getActiveDriver()` (thread-local state). Via is entirely
Selenium-coupled (`WebDriver`, `WebElement`, `By` etc.) and not a kernel class.
Driver-accepting overloads already exist. Fixing in this phase would require
either removing or deprecating the convenience overloads, which is broader scope
than the rule deliverable. Named exception, closes with the broader Via/Interactions
cleanup (9.x).

## Risks

### R1 (LOW) -- `EnumResolver.printEnumFormat` signature change

No callers found in the repo. Change is safe. WebDriverWait timeout is hardcoded to
10 s (consistent with Waiter's default); callers that need a different timeout already
have to use a driver-accepting overload.

### R2 (MEDIUM) -- VOIDBuilder public API surface

`VOIDBuilder.profile(DriverFactory.Profile)` cannot be changed without a breaking
public API change. It must remain a named exception until the I6.4 API surface
decision resolves it. No action taken in I4.5.

### R3 (LOW) -- ArchUnit rule subject set

The rule must NOT include `core.driver.*` itself (self-imports are trivially allowed)
and must NOT include `core.engine.selenium.*` (the permitted importer). Using
`noClasses().that().resideOutsideOfPackages(...)` is the correct shape; verify that
the predicate correctly excludes both allowed boundaries before committing.

---

## Physical Package Move Decision

**Decision: NO move in I4.5.** The dependency rule is the deliverable. A physical move
to `core/engine/selenium/driver/` (with class renames) would break every existing
import site. That work belongs in the dedicated backlog finding and is absorbed into
I6.4. If the move happens, the exception list in the ArchUnit rule collapses
automatically as each caller is migrated.

---

## Implementation Plan

1. **Fix D1**: Parameterize `EnumResolver.printEnumFormat(By, WebDriver)`. Remove
   `Waiter` import.
2. **Add ArchUnit rule**: New `DriverIsolationRulesTest` class. Rule: production
   classes outside `core.engine.selenium.*` and `core.driver.*` must not depend on
   `core.driver.*`. Exception set names D2-D9 with closing phases.
3. **Commit**: single commit covering audit + fix + rule.
