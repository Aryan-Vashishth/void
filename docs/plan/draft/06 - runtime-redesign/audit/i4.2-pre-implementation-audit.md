# I4.2 Pre-Implementation Audit -- EngineBootstrap Decoupling

**Date:** 2026-07-28
**Branch:** `initiative/runtime-redesign`
**Scope:** Exact change surface for I4.2 -- every file that must change, every ArchUnit gate
affected, and the specific driver import that is the exit criterion's target.

---

## Exit criterion (from plan)

> `core.engine` reaches zero `core.driver` imports, excluding `core.engine.selenium..`.

One import is responsible for the entire violation.

---

## B1 -- `EngineBootstrap` carries `DriverFactory.Profile` -- the only driver import in the contract package

**File:** `core/engine/EngineBootstrap.java`

```java
import core.driver.DriverFactory;                   // line 3 -- sole core.driver import in core.engine

public sealed interface EngineBootstrap
        permits EngineBootstrap.FromProfile {

    record FromProfile(DriverFactory.Profile profile) implements EngineBootstrap {}

    static EngineBootstrap fromProfile(DriverFactory.Profile profile) { return new FromProfile(profile); }
}
```

`DriverFactory.Profile` is a driver-layer type from `core.driver`. Its presence on the sealed
record means:
- The neutral contract package (`core.engine`) imports the Selenium-infrastructure package.
- Every `EngineRegistrar.create(EngineBootstrap)` implementor must pattern-match on a
  driver-layer type or throw an unsupported-operation error.
- A non-Selenium engine cannot implement the `FromProfile` path without depending on
  `core.driver`.

**Fix:** Replace `FromProfile(DriverFactory.Profile)` with an opaque settings carrier.
The driver-layer type leaves the sealed interface entirely. The `sealed` keyword is preserved
-- the closed hierarchy remains a contract invariant. `VOIDBuilder` (which still holds
`DriverFactory.Profile` on its public API, closing I6.4) does the translation before
constructing the bootstrap.

Pre-existing documentation: I4 pre-implementation audit A2; ADR-021 consequences note
(ADR-018 migration debt).

## B2 -- `SeleniumEngineRegistrar` pattern-matches on `FromProfile` -- downstream breakage

**File:** `core/engine/selenium/SeleniumEngineRegistrar.java`

```java
@Override
public UIEngine create(EngineBootstrap bootstrap) {
    if (bootstrap instanceof EngineBootstrap.FromProfile fp) {
        return new SeleniumEngine(fp.profile());
    }
    throw new IllegalArgumentException(
            "SeleniumEngine requires EngineBootstrap.FromProfile; got: "
            + bootstrap.getClass().getSimpleName());
}
```

When `FromProfile` is removed, this `instanceof` check breaks at compile time. The
registrar must be updated to read the profile from the replacement settings carrier.

`SeleniumEngine(DriverFactory.Profile profile)` stays intact -- `core.engine.selenium` is
allowed to import `core.driver`. The registrar reconstructs a `DriverFactory.Profile` from
the settings string (e.g., `DriverFactory.Profile.valueOf(name)`). All current `Profile`
enum values (`DEFAULT`, `CHROME`, `FIREFOX`, `EDGE`, `HEADLESS_CHROME`, `HEADLESS_FIREFOX`,
`REMOTE`, `CI`) are stable Java enum names, so `valueOf()` is reliable.

The profile-key constant (the string key used to store the profile name in settings) is owned
by `SeleniumEngineRegistrar`, not by `EngineBootstrap` -- the neutral contract must not know
about profile semantics.

## B3 -- `VOIDBuilder` -- public API unchanged, internal plumbing changes

**File:** `core/runtime/VOIDBuilder.java`

```java
private DriverFactory.Profile profile;                // field -- stays

public VOIDBuilder profile(DriverFactory.Profile profile) { ... }   // public method -- stays

// start():
UIEngineFactory.create(config,
    EngineBootstrap.fromProfile(profile != null ? profile : DriverFactory.Profile.DEFAULT));
    //               ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    //               This call changes -- fromProfile() goes away; replaced by
    //               a settings-based factory method
```

The only change in `VOIDBuilder` is the `EngineBootstrap` construction call inside `start()`.
The public method signature and the `DriverFactory.Profile` field are untouched.

`core.driver.DriverFactory` remains in VOIDBuilder's imports after 4.2 -- this is a
documented temporary exception in `KERNEL_PURITY_TEMPORARY_EXCEPTIONS` that closes at I6.4,
not here.

## B4 -- Replacement shape for `EngineBootstrap`

The replacement must satisfy three constraints:
1. No `core.driver` import in `EngineBootstrap.java`.
2. `sealed` is preserved (the contract controls what bootstrap variants exist).
3. Engine-owned settings are opaque by contract -- `EngineBootstrap` does not interpret them.

**Proposed replacement:**

```java
public sealed interface EngineBootstrap
        permits EngineBootstrap.WithSettings {

    /** Opaque, engine-owned settings. Key-value pairs whose meaning is defined by the registrar. */
    record WithSettings(Properties settings) implements EngineBootstrap {}

    static EngineBootstrap withSettings(Properties settings) { return new WithSettings(settings); }
}
```

`VOIDBuilder.start()` encodes its `DriverFactory.Profile` into the settings map before
constructing the bootstrap. `SeleniumEngineRegistrar` reads the profile name out and
reconstructs the enum. No other part of `core.engine` sees or interprets the settings.

`Properties` is a JDK type -- no new imports required in `EngineBootstrap.java`.

## B5 -- New ArchUnit fitness check required for exit criterion

The I4.2 exit criterion must be machine-verifiable. No rule in `KernelBoundaryRulesTest`
currently covers the `core.engine` (contract) -> `core.driver` edge.

**Rule to add:**

```java
@Test(description = "core.engine contract package has no core.driver dependency (I4.2)")
public void engineContractIsDriverFree() {
    ArchRule rule = noClasses()
            .that().resideInAPackage("core.engine")               // contract only; not core.engine.selenium..
            .should().dependOnClassesThat().resideInAPackage("core.driver..")
            .because(
                "The engine contract package must not import driver infrastructure. " +
                "SeleniumEngine and its registrar (core.engine.selenium) may import core.driver; " +
                "the contract package may not. runtime-redesign I4.2.");
    rule.check(allClasses);
}
```

Note: `resideInAPackage("core.engine")` matches only the exact package, not sub-packages,
so `core.engine.selenium` is automatically excluded.

## Change surface summary

| File | Change |
|------|--------|
| `core/engine/EngineBootstrap.java` | Remove `FromProfile(DriverFactory.Profile)`; add `WithSettings(Properties)` |
| `core/engine/selenium/SeleniumEngineRegistrar.java` | Replace `instanceof FromProfile` with settings read + `Profile.valueOf()` |
| `core/runtime/VOIDBuilder.java` | Change `EngineBootstrap.fromProfile(...)` call to `EngineBootstrap.withSettings(...)` with profile name encoded |
| `core/architecture/KernelBoundaryRulesTest.java` | Add `engineContractIsDriverFree()` test |

No other files are in scope. `SeleniumEngine.java` is not touched -- its constructor and
`initialize()` are unchanged. `UIEngineFactory.java` is not touched -- it receives and passes
`EngineBootstrap` opaquely, already indifferent to its variant.

## Risk register

| Risk | Severity | Mitigation |
|------|----------|------------|
| `Profile.valueOf(name)` throws on an unrecognized string if `VOIDBuilder` encodes incorrectly | Low | The encoding is `profile.name()` on a non-null enum value or the literal `"DEFAULT"` for the null case. Round-trip is exact. |
| Settings carrier becomes stringly-typed dumping ground | Medium | The profile key constant is owned by `SeleniumEngineRegistrar` and documented as engine-owned. `EngineBootstrap.WithSettings` has no knowledge of key semantics. |
| `Properties` object is mutable; a registrar could mutate it after construction | Low | `SeleniumEngineRegistrar` constructs a defensive copy at read time, or `VOIDBuilder` passes `new Properties(source)`. |

---

## Verdict

**READY.** Change surface is exactly four files. One `import` is removed from the contract
package; the sealed interface's variant changes. Downstream impact is contained to
`SeleniumEngineRegistrar` and `VOIDBuilder.start()`. The kernel purity gate requires no
modification. One new ArchUnit rule closes the exit criterion.
