# I4.4 Pre-Implementation Audit

**Phase:** runtime-redesign I4.4 -- Retype kernel execution edges to `Executor`
**Date:** 2026-07-28
**Verdict:** READY -- no blockers; two overload-resolution risks require care

---

## Scope Reminder

Retype the kernel's primary execution edges (`Action.perform`, `ActionHandler.execute`,
`FlowExecutor` constructor/field) from `UIEngine` to the neutral `Executor` contract.
Deprecated UIEngine-typed bridges remain so external consumers compile unchanged.
All in-repo callers migrate off bridges. The UIEngineFactory bridge cast and session
wiring (VOID, SessionContext, VOIDBuilder) are NOT in scope.

---

## Findings

### D1 -- `Action.perform(UIEngine)` and `resolve(UIEngine)`: `@FunctionalInterface` constraint

**File:** `src/main/java/core/actions/Action.java`

`Action` is annotated `@FunctionalInterface`, which permits exactly one abstract method.
The current SAM is `void perform(UIEngine engine)`.

After I4.4 the SAM must be `void perform(Executor executor)`. The UIEngine-typed bridge
**must** be a `default` method (not abstract), or the interface is no longer functional.

`resolve(UIEngine)` is already a `default` method that throws; it changes to
`default resolve(Executor)`. The UIEngine-typed bridge becomes a second `default`.

No structural hazard -- both bridges can be `default`. Confirm the abstract count stays
at one before committing.

**Risk:** LOW. Mechanical.

---

### D2 -- `ActionHandler.execute(UIEngine, LocatorDescriptor)`: hook contract retype

**File:** `src/main/java/core/actions/hooks/ActionHandler.java`

`ActionHandler` is a `@FunctionalInterface` with SAM
`void execute(UIEngine engine, @Nullable LocatorDescriptor descriptor)`.

Same constraint as D1: `execute(Executor, LocatorDescriptor)` becomes the new SAM;
`execute(UIEngine, LocatorDescriptor)` becomes a `default` bridge.

`BeforeActionHandler` and `AfterActionHandler` are marker sub-interfaces that inherit
the bridge from `ActionHandler`. No changes needed to those two files.

The `legacy(Consumer<UIEngine>)` static factory:
```java
static ActionHandler legacy(Consumer<UIEngine> handler) {
    return (engine, descriptor) -> handler.accept(engine);
}
```
After the SAM retyping the lambda parameter `engine` is `Executor`. The body calls
`handler.accept(engine)` which expects `UIEngine` -- compile error. The factory itself
is already a deprecated bridge; add a cast inside:
```java
return (executor, descriptor) -> handler.accept((UIEngine) executor);
```

**Risk:** LOW if the cast is added; compile error if missed.

### D3 -- `FlowExecutor`: field and constructor retype; one in-repo call site

**File:** `src/main/java/core/executor/FlowExecutor.java`

`private final UIEngine engine` -- field type changes to `Executor`.
`public FlowExecutor(UIEngine engine)` -- constructor type changes to `Executor`.

Because `UIEngine extends Executor`, external code that was doing
`new FlowExecutor(uiEngineVar)` continues to compile without a bridge constructor.
Java resolves the single `FlowExecutor(Executor)` constructor via widening.

**In-repo call site -- `VOID.java`:**
```java
this.executor = new FlowExecutor(engine);  // engine is UIEngine -- widens to Executor OK
```
This compiles and routes to the primary constructor directly. No cast or bridge needed
here. The concern would only arise if a deprecated `FlowExecutor(UIEngine)` bridge
existed alongside the primary -- the bridge would win on specificity. Since there is
no bridge planned for the constructor (widening handles it), VOID.java needs no change.

`FlowExecutor.run()` calls `action.perform(engine)`. After the field is `Executor`,
`engine` is typed as `Executor` at the call site, so Java resolves `perform(Executor)`
(the new primary), not `perform(UIEngine)` (the bridge). No cast required.

**Risk:** LOW. No bridge constructor needed; widening covers all callers.

### D4 -- `HookChainAction`: full internal migration

**File:** `src/main/java/core/actions/HookChainAction.java`

Four sites change:

| Site | Before | After |
|---|---|---|
| `perform` override | `void perform(UIEngine engine)` | `void perform(Executor executor)` |
| `performAndTrace` internal | `ActionTrace performAndTrace(UIEngine engine)` | `ActionTrace performAndTrace(Executor executor)` |
| `resolve` override | `LocatorDescriptor resolve(UIEngine engine)` | `LocatorDescriptor resolve(Executor executor)` |
| `forTesting()` anonymous class | overrides `perform(UIEngine)`, `resolve(UIEngine)` | overrides `perform(Executor)`, `resolve(Executor)` |

**Bridge discipline:** `perform(UIEngine)` (the inherited deprecated default from `Action`)
must NOT be overridden by `HookChainAction`. If `HookChainAction` added its own
`perform(UIEngine)` override, it would shadow the `Action` interface's bridge default
and could duplicate `performAndTrace` logic. Leave the bridge on the interface only.

**`forTesting()` anonymous class risk (MEDIUM):** The anonymous class currently
overrides `perform(UIEngine)` and `resolve(UIEngine)`. After the SAM changes to
`perform(Executor)`, the anonymous class's `perform(UIEngine)` override would match
only the deprecated bridge method, not the new SAM. The class would still compile
(it provides a `default` override of the bridge), but the primary path
`perform(Executor)` would be unimplemented and fall through to `Action`'s bridge
default, which calls `perform(UIEngine)` -- infinite loop in examples.

**Fix:** Change the anonymous class overrides to `perform(Executor)` and
`resolve(Executor)`, casting to UIEngine internally where needed.

**Inside `performAndTrace(Executor)`:** calls to `hook.execute(engine, descriptor)` and
`delegate.perform(engine)` work because `engine` is now typed as `Executor`, which
selects `ActionHandler.execute(Executor, descriptor)` and `Action.perform(Executor)`
-- both primaries. No casts needed inside `performAndTrace`.

**Risk:** D4 overall MEDIUM due to the `forTesting()` anonymous class trap.

### D5 -- `ElementAction` and 17 concrete action classes: web-domain migration

**Files:**
- `src/main/java/elements/api/actions/ElementAction.java`
- All 17 concrete subclasses (`ClickAction`, `TypeAction`, `ClearAction`, etc.)

`ElementAction` currently declares `abstract void perform(UIEngine engine)` and
`abstract LocatorDescriptor resolve(UIEngine engine)`. These change to:
```java
@Override public abstract void perform(Executor executor);
@Override public abstract LocatorDescriptor resolve(Executor executor);
```

Every concrete subclass overrides `perform(UIEngine)` and `resolve(UIEngine)`. Each
must switch to `perform(Executor executor)` and `resolve(Executor executor)`, then cast
at the top of the method body to access UIEngine methods:
```java
UIEngine engine = (UIEngine) executor;
```

This cast is safe for the lifetime of these classes -- only `UIEngine` instances reach
them through the VOID session facade. It mirrors the same pattern as domain-side
`LocatorResolver` working with Selenium-specific types internally while accepting
neutral contracts at the boundary.

`ElementActions.java` (the static factory that builds `ElementAction` instances) does
not call `perform()` or `resolve()` directly; it should not need changes unless it
creates ActionHandler lambdas with UIEngine parameters (check during implementation).

**Risk:** LOW per file; HIGH in aggregate -- 18 files to update, all mechanical.

### D6 -- `core.interactions.hooks.Before` and `After`: frozen legacy hook lambdas

**Files:**
- `src/main/java/core/interactions/hooks/Before.java`
- `src/main/java/core/interactions/hooks/After.java`

These contain `BeforeActionHandler`/`AfterActionHandler` constants as lambdas:
```java
public static final BeforeActionHandler HIGHLIGHT =
    (engine, descriptor) -> engine.highlight(descriptor, "#FFD700");
```

After `ActionHandler.execute()` is retyped, the lambda parameter `engine` becomes
`Executor`. Calls like `engine.highlight(...)` are UIEngine-only methods -- compile
error.

These files are in the frozen legacy zone but must be touched mechanically. Every
lambda that calls UIEngine methods on `engine` adds a local cast:
```java
(executor, descriptor) -> {
    UIEngine engine = (UIEngine) executor;
    engine.highlight(descriptor, "#FFD700");
}
```

The cast is safe -- `BeforeActionHandler`/`AfterActionHandler` are fed only by
`HookChainAction.performAndTrace()`, which receives a `UIEngine`-backed `Executor`
in all current sessions.

Count the lambdas in both files during implementation and confirm each is updated.
Do not leave any lambda with a direct UIEngine method call on the Executor-typed
parameter.

**Risk:** MEDIUM -- easy to miss a lambda; compile will catch it.

### D7 -- `UIEngineFactory.create()` bridge cast: stays unchanged

**File:** `src/main/java/core/engine/UIEngineFactory.java`

The I4.3 bridge cast:
```java
UIEngine engine = (UIEngine) registrar.create(bootstrap);
```

Stays in I4.4. The method signature `UIEngine create(Properties, EngineBootstrap)`
stays. The full session-wiring retype (UIEngineFactory, VOIDBuilder, SessionContext,
VOID) is a separate future phase. No changes here.

**Risk:** NONE for this phase.

### D8 -- Kernel purity gate: close `UIEngine` exception, add `Executor`

**File:** `src/test/java/core/architecture/KernelBoundaryRulesTest.java`

`KERNEL_PURITY_TEMPORARY_EXCEPTIONS` currently includes `core.engine.UIEngine`.

After I4.4:
- Remove `"core.engine.UIEngine"` from the set.
- Add `"core.engine.Executor"` (the new permitted kernel reference).

The existing `executorContractIsNeutral()` test (added in I4.3) already gates
`core.engine.Executor` for no Selenium or elements dependencies. The purity gate
removal of `UIEngine` means the 22 (now 22) examples must pass with the kernel packages
having no remaining UIEngine dependency.

Verify no kernel class other than the deprecated bridge paths imports `core.engine.UIEngine`
after the retype. If any stray import survives, the gate catches it.

**Risk:** LOW -- the gate is self-verifying; any missed UIEngine reference fails CI.

## Exit Criteria

- `Action` has exactly one abstract method (`perform(Executor)`).
- `ActionHandler` has exactly one abstract method (`execute(Executor, LocatorDescriptor)`).
- `FlowExecutor` field and constructor parameter are typed `Executor`.
- No kernel class (core.actions, core.executor, core.flow, core.context, core.runtime,
  core.bootstrap) imports `core.engine.UIEngine` except in `@Deprecated` bridge paths.
- All 17 concrete element actions compile with the new override signatures.
- `Before` and `After` lambda constants compile without UIEngine-typed parameters.
- `KernelBoundaryRulesTest` passes with `UIEngine` removed from temporary exceptions
  and `Executor` added.
- No in-repo caller invokes a deprecated bridge method except the bridge-verification
  examples added in this phase.

**Verdict: READY**
