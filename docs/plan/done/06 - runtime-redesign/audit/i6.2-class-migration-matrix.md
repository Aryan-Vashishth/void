### Classification notes

**`UIEngine` as Web Vocabulary (WV) not Implementation (WI):**
`UIEngine` is the Web domain's execution contract -- the declaration of what a web executor can do. It is logically vocabulary (it defines the web domain's capability surface) even though it is also implemented by `SeleniumEngine`. The distinction maps to guardrail rule 8: vocabulary vs. implementation. `UIEngine` is placed in WV because a future Playwright executor implements the same vocabulary -- it does not introduce new vocabulary. The physical sub-package (`domain.automation.web.engine`) reflects this by separating the contract (`UIEngine`) from the implementation (`SeleniumEngine`).

**`EngineConfig` as Kernel (K) not Web Implementation:**
`EngineConfig` carries `defaultTimeout`, `pollingInterval`, and `baseUrl` -- all generic executor parameters applicable to any domain (REST executor, database executor). No web-specific or Selenium-specific fields exist. It is the parameter type for `Executor.initialize(EngineConfig)` on the kernel-neutral contract. Moving `EngineConfig` to `domain.automation.web.*` would create a kernel-to-domain dependency via `Executor.initialize()`, violating kernel purity. It stays in `core.engine`.

**`elements.locator.*` as Web Implementation (WI) not Vocabulary:**
LocatorDescriptor and LocatorStrategy describe how UI elements are addressed (DOM locators, CSS selectors, XPath). This is implementation-layer knowledge (the Web domain's mechanism for finding elements), not vocabulary (what elements ARE). A future Playwright domain would use the same mechanism, so it's not purely web-specific -- but for now it is a web-domain intermediate home (ADR-019, I7.2) and the matrix records it as WI pending the I9.4 vocabulary-reclaim decision.
